# prs-methods-core

SDK для внешних методов платформы [Peresvet](https://github.com/mp-co-ru/peresvet).

Как методы устроены на стороне платформы, описано в документации Peresvet:
[раздел «Методы»](https://mp-co-ru.github.io/peresvet/methods.html). Там рассказано
про типы методов, источники параметров, каталог методов и ссылки на него.

**Метод** — функция на Python, которую платформа вызывает, чтобы посчитать
значение тега, ответить на чтение тега или принять запись в тег.
Функция работает не внутри платформы, а в вашем процессе — **исполнителе**.
Исполнитель подключается к RabbitMQ платформы и ждёт вызовов.

```
 Платформа Peresvet                          Ваш исполнитель
 ──────────────────                          ───────────────
 событие (новое значение тега,
 расписание, чтение, запись)
        │
 собирает аргументы метода  ── RabbitMQ ──►  @method("acme.energy.sum")
                                             def sum_energy(a, b): ...
 записывает результат в тег ◄── RabbitMQ ──  return 5
```

SDK берёт на себя подключение к RabbitMQ, разбор аргументов, обработку ошибок
и описание методов для каталога платформы. Вам остаётся написать функцию.

Сначала выберите, какой метод вам нужен ([Какие бывают методы](#какие-бывают-методы)),
затем пройдите [Быстрый старт](#быстрый-старт).

## Какие бывают методы

На платформе пять типов методов. Тип выбирают в ссылке на метод под тегом,
а не в коде. От типа зависит, когда платформа вызывает функцию, что передаёт
и что делает с результатом. Подробнее — в документации Peresvet,
[«Методы», раздел «Типы методов»](https://mp-co-ru.github.io/peresvet/methods.html).

| Код | Тип | Когда вызывается | Аргументы функции | Что делает платформа с результатом |
| --- | --- | --- | --- | --- |
| 0 | [Вычислительный](#0-вычислительный) | Новое значение тега-инициатора, срабатывание расписания | Параметры | Записывает в тег |
| 1 | [Чтение](#1-чтение) | Клиент читает тег | Параметры | Отдаёт клиенту как значение тега |
| 2 | [Запись](#2-запись) | Клиент пишет в тег | Параметры, затем записываемые точки | `fail` — отказ в записи, иначе запись принята |
| 3 | [Действие при чтении](#3-действие-при-чтении) | Клиент читает тег | Параметры | Игнорирует, ошибки только в журнал |
| 4 | [Действие при записи](#4-действие-при-записи) | Клиент пишет в тег | Параметры, затем записываемые точки | Игнорирует, ошибки только в журнал |

Кроме типа, у каждого метода либо **фиксированный** список параметров, либо
**произвольный** (см. [Фиксированные и произвольные параметры](#фиксированные-и-произвольные-параметры)).
Любой тип может быть и таким, и таким.

Примеры по типам:

| Тип | Фиксированные параметры | Произвольные параметры |
| --- | --- | --- |
| 0 Вычислительный | [`compute_sum.py`](examples/compute_sum.py) — сумма двух тегов | [`compute_total.py`](examples/compute_total.py) — сумма любого числа тегов |
| 1 Чтение | [`read_tariff.py`](examples/read_tariff.py) — тариф на момент запроса | [`read_average.py`](examples/read_average.py) — среднее по любому числу датчиков |
| 2 Запись | [`write_setpoint.py`](examples/write_setpoint.py) — проверка уставки и передача на оборудование | — |
| 3 Действие при чтении | [`read_audit.py`](examples/read_audit.py) — журнал чтений тега | — |
| 4 Действие при записи | [`write_alarm.py`](examples/write_alarm.py) — оповещение о превышении порога | — |

В начале каждого примера написано, как настроить его на платформе.
Во фрагментах ниже импорты опущены: все функции берутся из `prs_methods`.

### 0. Вычислительный

Платформа вызывает метод при каждом новом значении тега-инициатора
или срабатывании расписания. Параметры, которые читают теги, получают значения
на момент этого события. Результат записывается в тег, которому принадлежит
метод, с меткой времени события.

```python
@method("acme.energy.sum", parameters=(param("a"), param("b")), probe=(2, 3))
def sum_energy(a, b):
    require_good(a, b)
    return number(a) + number(b)
```

### 1. Чтение

У тега нет хранимых значений: когда клиент читает тег (`GET /v1/data/`), значение
вычисляет метод. Параметры-теги читаются на момент `finish` из запроса клиента.
Сам запрос можно получить параметром «Данные из запроса клиента».
Результат функции клиент получит как значение тега на момент `finish`.

```python
@method(
    "acme.energy.tariff",
    parameters=(param("request", "json"), param("day"), param("night")),
    probe=({"finish": 1_700_000_000_000_000}, 6.5, 2.5),
)
def tariff(request, day, night):
    hour = moment(request["finish"]).astimezone(MOSCOW).hour
    return number(day) if 7 <= hour < 23 else number(night)
```

Тег с методом чтения не привязывают к хранилищу, иначе на чтение ответят
и хранилище, и метод, а клиент получит тот ответ, который придёт первым.

### 2. Запись

Метод принимает запись в тег (`POST /v1/data/`) вместо хранилища. Записываемые
точки приходят **последним аргументом**, после всех параметров, поэтому у функции
на один аргумент больше, чем в `parameters`. `fail` отклоняет запись,
и клиент получает ошибку. Возвращаемое значение не используется.

```python
@method(
    "acme.hvac.setpoint_write",
    parameters=(param("limit"),),
    probe=(30, [[1_700_000_000_000_000, 21, None]]),
)
def setpoint_write(limit, written):
    for item in points(written):
        if not 0 <= number(item.y) <= number(limit):
            fail(f"уставка {item.y} вне диапазона")
    send_to_controller(written)
    return True
```

Как и тег с методом чтения, тег с методом записи не привязывают к хранилищу.

### 3. Действие при чтении

Вызывается при каждом чтении тега, но значение клиенту отдаёт хранилище,
а не метод. Подходит для побочных действий: журнал, статистика, прогрев кэша.
Результат функции и `fail` на чтение не влияют, ошибки попадают только в журнал платформы.

```python
@method("acme.audit.read", parameters=(param("request", "json"),), probe=({"tagId": ["1"]},))
def audit_read(request):
    log.warning("чтение тегов %s", request.get("tagId"))
    return True
```

### 4. Действие при записи

Вызывается при каждой записи в тег. Записываемые точки, как и у метода записи,
приходят последним аргументом, но сохраняет их хранилище, и отклонить запись
метод не может. Подходит для оповещений и пересылки данных в другие системы.

```python
@method(
    "acme.alarm.pressure",
    parameters=(param("limit"),),
    probe=(6, [[1_700_000_000_000_000, 6.4, None]]),
)
def pressure_alarm(limit, written):
    for item in points(written):
        if is_good(item.q) and number(item.y) > number(limit):
            notify(f"давление {item.y} выше порога")
    return True
```

Если у тега нет ни хранилища, ни метода записи, платформа сама подтверждает запись
после выполнения действия.

## Фиксированные и произвольные параметры

**Фиксированные параметры** — метод всегда получает одно и то же число аргументов.
Их перечисляют в `parameters`, по одному `param(...)` на аргумент функции.
Ссылка на такой метод должна задать ровно столько параметров. Если число не совпадает,
платформа не вызывает метод и пишет ошибку в журнал.

```python
@method("acme.energy.sum", parameters=(param("a", "float"), param("b", "float")))
def sum_energy(a, b):
    return number(a) + number(b)
```

**Произвольные параметры** — каждая ссылка сама решает, сколько параметров передать.
Например, «сумма всех комнат этажа», когда на разных этажах разное число комнат.
Укажите `variadic=True` вместо `parameters`, а функция пусть принимает `*args`:

```python
@method("acme.energy.total", variadic=True, probe=(1, 2, 3))
def total(*args):
    if not args:
        fail("у ссылки на метод нет ни одного параметра")
    return sum(number(arg) for arg in args)
```

Особенности произвольных параметров:

- аргументы по-прежнему приходят в порядке `prsIndex` параметров ссылки;
- у метода записи и действия при записи записываемые точки всё равно идут последними:
  `def f(*args)`, где `args[-1]` — точки;
- задавайте `probe`: без него пробный вызов придёт совсем без аргументов;
- **загрузчик описания платформы пока не переносит флаг `variadic`.** После загрузки
  откройте определение метода в каталоге и включите «Произвольные параметры»
  (через API — `PUT /v1/methods/` с атрибутом `prsVariadic: true`).
  Пока флаг не включён, платформа будет требовать у ссылок ноль параметров.

## Быстрый старт

### 1. Установка

Нужен Python 3.11 или новее.

```bash
pip install -e .
```

### 2. Напишите метод

```python
# my_methods.py
from prs_methods import main, method, number, param


@method(
    "acme.energy.sum",                    # адрес, по которому платформа вызывает метод
    cn="Сумма",                           # название в каталоге
    folder="Энергия",                     # папка в каталоге
    parameters=(param("a", "float"), param("b", "float")),
    probe=(2, 3),                         # аргументы пробного вызова после загрузки
)
def sum_energy(a, b):
    return number(a) + number(b)


if __name__ == "__main__":
    main()      # с ключом --yaml печатает описание для каталога, без ключа запускает исполнитель
```

`number(a)` достаёт число из аргумента в любой форме, в которой его может прислать
платформа (подробнее в разделе [Что приходит в аргументы](#что-приходит-в-аргументы)).
Это вычислительный метод с фиксированными параметрами. Другие варианты — в разделе
[Какие бывают методы](#какие-бывают-методы).

### 3. Проверьте метод без платформы

Декоратор не меняет функцию, поэтому её можно вызывать напрямую:

```python
from my_methods import sum_energy

assert sum_energy(2, 3) == 5
assert sum_energy({"data": [{"tagId": "1", "data": [[0, 2, None]]}]}, 3) == 5
```

### 4. Загрузите описание в каталог платформы

```bash
python my_methods.py --yaml > methods.yaml
```

В конфигураторе откройте меню папки «Методы», выберите «Загрузка описания»
и укажите файл `methods.yaml`. Через API это запрос `POST /v1/methods/description`
с полями `yaml` (текст файла) и `parentId` (папка каталога).

Если отметить «Проверить методы» (в API — `probe: true`), платформа сразу после
загрузки вызовет каждый метод с аргументами из `probe` и покажет результат.
Для этого исполнитель (шаг 6) должен быть уже запущен.

### 5. Подключите метод к тегу

В меню тега, в который нужно записывать результат, выберите «Новый метод»,
затем «Ссылка на метод из каталога», и выберите метод. В ссылке укажите:

- **тип** — когда вызывать метод (см. [Какие бывают методы](#какие-бывают-методы));
- **инициаторы** — теги или расписания, которые запускают расчёт;
- **параметры** — откуда брать значение каждого аргумента: другой тег,
  литерал, константа и т. д.

### 6. Запустите исполнитель

```bash
amqp_url=amqp://пользователь:пароль@сервер/ python my_methods.py
```

Исполнитель работает, пока его не остановят, и сам переподключается при обрыве связи.
Его можно запускать на любой машине, откуда доступен RabbitMQ платформы (порт 5672).

## Что приходит в аргументы

Платформа передаёт аргументы позиционно, в порядке параметров метода.
Форма аргумента зависит от того, как параметр настроен в ссылке на метод:

| Источник параметра | Что получит функция |
| --- | --- |
| Литерал, константа, JSONata, пробный вызов | Готовое значение: `2`, `"текст"`, `{...}` |
| Тег (данные тега, привязка к тегу) | Ответ чтения: `{"data": [{"tagId": "...", "data": [[x, y, q]]}]}` |
| Запрос клиента, если метод запущен событием | `{"finish": ..., "start": None, "point": {"x": ..., "y": ..., "q": ...}}` |
| Записываемые точки (методы записи) | Последний аргумент: `[[x, y, q], ...]` |

Точка тега — `[x, y, q]`:

- `x` — метка времени, целое число микросекунд от 1970-01-01 UTC;
- `y` — значение;
- `q` — код качества: `None` или `0` — годное значение, `100`–`103` — проблемы со связью
  или источником данных.

Вручную разбирать эти формы не нужно, для этого есть функции:

| Функция | Что возвращает |
| --- | --- |
| `number(arg)` | Последнее значение как число. Если значения нет или это не число — `fail` |
| `value(arg)` | Последнее значение любого типа или `None` |
| `point(arg)` | Последнюю точку: `Point(x, y, q)` |
| `points(arg)` | Все точки одного тега, от старых к новым |
| `readings(arg)` | Точки по каждому тегу, если параметр читает несколько тегов |
| `moment(x)` | Метку времени как `datetime` в UTC |
| `is_good(q)` | `True`, если качество годное |
| `require_good(a, b, ...)` | Ничего. Если данных нет или качество плохое — `fail` |

## Что возвращать

- **Значение** (число, строка, список, словарь) платформа записывает в тег.
  Метка времени — время события, запустившего метод.
- **`fail("причина")`** прерывает метод. Значение тега не меняется,
  причина попадает в журнал платформы.
- **Любое необработанное исключение** работает так же, как `fail`. Текст в журнале
  начинается с имени исключения, например `ZeroDivisionError: division by zero`.
  Исполнитель при этом продолжает работать.

```python
from prs_methods import fail, method, number, require_good

@method("acme.energy.ratio")
def ratio(a, b):
    require_good(a, b)          # нет данных или потеряна связь — тег не меняется
    divisor = number(b)
    if divisor == 0:
        fail("деление на ноль")
    return number(a) / divisor
```

Функция может быть как обычной, так и `async`: `async` удобен, если метод
ходит в сеть или базу данных.

## Описание для каталога

У `@method` обязателен только адрес. Остальные аргументы попадают в описание каталога:

| Аргумент | Назначение |
| --- | --- |
| `address` | Адрес вызова. Должен быть уникальным среди всех исполнителей платформы, удобно начинать с имени организации: `acme.<область>.<метод>` |
| `cn` | Название в каталоге. По умолчанию — имя функции |
| `description` | Описание. По умолчанию — docstring функции |
| `parameters` | Фиксированные параметры: `param(название, тип, описание)` на каждый аргумент, в том же порядке |
| `variadic` | `True` — произвольное число параметров, `parameters` не указываются |
| `probe` | Аргументы пробного вызова после загрузки описания |
| `folder`, `folder_description` | Папка в каталоге «Методы» и её описание |

Тип параметра — `int`, `float`, `string` или `json`. Платформа не проверяет тип
при вызове: он подсказывает человеку, что подставить, и задаёт пробное значение,
если `probe` не указан. Платформа проверяет только число параметров
у ссылки на метод, а у метода с `variadic=True` не проверяет и его.

Если адрес метода в каталоге изменят, ссылки сразу начнут вызывать новый адрес.
Повторная загрузка описания не создаёт метод, адрес которого уже есть в каталоге.

## Тесты

Функцию метода можно вызывать напрямую, как в шаге 3. Чтобы проверить метод
так, как его вызывает платформа, включая превращение `fail` в `{"error": ...}`,
возьмите обёртку из реестра:

```python
import asyncio
from prs_methods import registry

result = asyncio.run(registry["acme.energy.ratio"](4, 0))
assert result == {"error": "деление на ноль"}
```

Тесты самого SDK:

```bash
pip install -e ".[dev]"
pytest
```
