# prs-methods-core

SDK для внешних методов платформы [Peresvet](https://github.com/mp-co-ru/mpc-peresvet).

**Метод** — функция на Python, которую платформа вызывает, чтобы посчитать
значение тега, ответить на чтение тега или принять запись в тег.
Функция работает не внутри платформы, а в вашем процессе — **исполнителе**.
Исполнитель подключается к RabbitMQ платформы и ждёт вызовов.

```
 Платформа Peresvet                          Ваш исполнитель
 ──────────────────                          ───────────────
 событие (новое значение тега,
 расписание, чтение, запись)
        │
 собирает аргументы метода  ── RabbitMQ ──►  @method("acme.energy.sum")
                                             def sum_energy(a, b): ...
 записывает результат в тег ◄── RabbitMQ ──  return 5
```

SDK берёт на себя подключение к RabbitMQ, разбор аргументов, обработку ошибок
и описание методов для каталога платформы. Вам остаётся написать функцию.

## Быстрый старт

### 1. Установка

Нужен Python 3.11 или новее.

```bash
pip install -e .
```

### 2. Напишите метод

```python
# my_methods.py
import sys

from prs_methods import description_yaml, method, number, param, run


@method(
    "acme.energy.sum",                    # адрес, по которому платформа вызывает метод
    cn="Сумма",                           # название в каталоге
    folder="Энергия",                     # папка в каталоге
    parameters=(param("a", "float"), param("b", "float")),
    probe=(2, 3),                         # аргументы пробного вызова после загрузки
)
def sum_energy(a, b):
    return number(a) + number(b)


if __name__ == "__main__":
    if "--yaml" in sys.argv:
        print(description_yaml(), end="")
    else:
        run()
```

`number(a)` достаёт число из аргумента в любой форме, в которой его может прислать
платформа (подробнее в разделе [Что приходит в аргументы](#что-приходит-в-аргументы)).

### 3. Проверьте метод без платформы

Декоратор не меняет функцию, поэтому её можно вызывать напрямую:

```python
from my_methods import sum_energy

assert sum_energy(2, 3) == 5
assert sum_energy({"data": [{"tagId": "1", "data": [[0, 2, None]]}]}, 3) == 5
```

### 4. Загрузите описание в каталог платформы

```bash
python my_methods.py --yaml > methods.yaml
```

В конфигураторе откройте меню папки «Методы», выберите «Загрузка описания»
и укажите файл `methods.yaml`. Через API это запрос `POST /v1/methods/description`
с полями `yaml` (текст файла) и `parentId` (папка каталога).

Если отметить «Проверить методы» (в API — `probe: true`), платформа сразу после
загрузки вызовет каждый метод с аргументами из `probe` и покажет результат.
Для этого исполнитель (шаг 6) должен быть уже запущен.

### 5. Подключите метод к тегу

В меню тега, в который нужно записывать результат, выберите «Новый метод»,
затем «Ссылка на метод из каталога», и выберите метод. В ссылке укажите:

- **тип** — когда вызывать метод (см. [Типы методов](#типы-методов));
- **инициаторы** — теги или расписания, которые запускают расчёт;
- **параметры** — откуда брать значение каждого аргумента: другой тег,
  литерал, константа и т. д.

### 6. Запустите исполнитель

```bash
amqp_url=amqp://пользователь:пароль@сервер/ python my_methods.py
```

Исполнитель работает, пока его не остановят, и сам переподключается при обрыве связи.
Его можно запускать на любой машине, откуда доступен RabbitMQ платформы (порт 5672).

## Что приходит в аргументы

Платформа передаёт аргументы позиционно, в порядке параметров метода.
Форма аргумента зависит от того, как параметр настроен в ссылке на метод:

| Источник параметра | Что получит функция |
| --- | --- |
| Литерал, константа, JSONata, пробный вызов | Готовое значение: `2`, `"текст"`, `{...}` |
| Тег (данные тега, привязка к тегу) | Ответ чтения: `{"data": [{"tagId": "...", "data": [[x, y, q]]}]}` |
| Запрос клиента, если метод запущен событием | `{"finish": ..., "start": None, "point": {"x": ..., "y": ..., "q": ...}}` |
| Записываемые точки (методы записи) | Последний аргумент: `[[x, y, q], ...]` |

Точка тега — `[x, y, q]`:

- `x` — метка времени, целое число микросекунд от 1970-01-01 UTC;
- `y` — значение;
- `q` — код качества: `None` или `0` — годное значение, `100`–`103` — проблемы со связью
  или источником данных.

Вручную разбирать эти формы не нужно, для этого есть функции:

| Функция | Что возвращает |
| --- | --- |
| `number(arg)` | Последнее значение как число. Если значения нет или это не число — `fail` |
| `value(arg)` | Последнее значение любого типа или `None` |
| `point(arg)` | Последнюю точку: `Point(x, y, q)` |
| `points(arg)` | Все точки одного тега, от старых к новым |
| `readings(arg)` | Точки по каждому тегу, если параметр читает несколько тегов |
| `moment(x)` | Метку времени как `datetime` в UTC |
| `is_good(q)` | `True`, если качество годное |
| `require_good(a, b, ...)` | Ничего. Если данных нет или качество плохое — `fail` |

## Что возвращать

- **Значение** (число, строка, список, словарь) платформа записывает в тег.
  Метка времени — время события, запустившего метод.
- **`fail("причина")`** прерывает метод. Значение тега не меняется,
  причина попадает в журнал платформы.
- **Любое необработанное исключение** работает так же, как `fail`. Текст в журнале
  начинается с имени исключения, например `ZeroDivisionError: division by zero`.
  Исполнитель при этом продолжает работать.

```python
from prs_methods import fail, method, number, require_good

@method("acme.energy.ratio")
def ratio(a, b):
    require_good(a, b)          # нет данных или потеряна связь — тег не меняется
    divisor = number(b)
    if divisor == 0:
        fail("деление на ноль")
    return number(a) / divisor
```

Функция может быть как обычной, так и `async`: `async` удобен, если метод
ходит в сеть или базу данных.

## Типы методов

Тип задаётся в ссылке на метод под тегом, а не в коде. Одна и та же функция
может работать с разными типами, если принимает подходящие аргументы.

| Код | Тип | Когда вызывается | Аргументы | Результат |
| --- | --- | --- | --- | --- |
| 0 | Вычислительный | Новое значение инициатора, срабатывание расписания | Параметры | Записывается в тег |
| 1 | Чтение | Клиент читает тег | Параметры | Отдаётся клиенту как значение тега |
| 2 | Запись | Клиент пишет в тег | Параметры и записываемые точки | `fail` — отказ в записи, иначе запись принята |
| 3 | Действие при чтении | Клиент читает тег | Параметры | Не используется, ошибки только в журнал |
| 4 | Действие при записи | Клиент пишет в тег | Параметры и записываемые точки | Не используется, ошибки только в журнал |

Тег с методом типа 1 или 2 обычно не привязывают к хранилищу, иначе на чтение
или запись ответят и хранилище, и метод.

Пример метода записи — [`examples/setpoint_write.py`](examples/setpoint_write.py).

## Описание для каталога

У `@method` обязателен только адрес. Остальные аргументы попадают в описание каталога:

| Аргумент | Назначение |
| --- | --- |
| `address` | Адрес вызова. Должен быть уникальным среди всех исполнителей платформы, удобно начинать с имени организации: `acme.<область>.<метод>` |
| `cn` | Название в каталоге. По умолчанию — имя функции |
| `description` | Описание. По умолчанию — docstring функции |
| `parameters` | Параметры: `param(название, тип, описание)` на каждый аргумент, в том же порядке |
| `probe` | Аргументы пробного вызова после загрузки описания |
| `folder`, `folder_description` | Папка в каталоге «Методы» и её описание |

Тип параметра — `int`, `float`, `string` или `json`. Платформа не проверяет тип
при вызове: он подсказывает человеку, что подставить, и задаёт пробное значение,
если `probe` не указан. Платформа проверяет только число параметров
у ссылки на метод.

Если адрес метода в каталоге изменят, ссылки сразу начнут вызывать новый адрес.
Повторная загрузка описания не создаёт метод, адрес которого уже есть в каталоге.

## Тесты

Функцию метода можно вызывать напрямую, как в шаге 3. Чтобы проверить метод
так, как его вызывает платформа, включая превращение `fail` в `{"error": ...}`,
возьмите обёртку из реестра:

```python
import asyncio
from prs_methods import registry

result = asyncio.run(registry["acme.energy.ratio"](4, 0))
assert result == {"error": "деление на ноль"}
```

Тесты самого SDK:

```bash
pip install -e ".[dev]"
pytest
```
